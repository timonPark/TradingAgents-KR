# [#194] 네이버 증권 종목뉴스 API 의 일시적 502 에 쪽 하나만 실패해도 뉴스 전체가 DATA_UNAVAILABLE

## 수행한 변경

- `tradingagents/dataflows/vendors/naver_news.py`
  - `_TransientVendorError(VendorUnavailableError)` 신규: 5xx·네트워크 오류를 다시 부를 수
    있는 실패로 구분. 상위 클래스가 같아서 라우터나 주요뉴스 쪽 처리는 바뀌지 않는다.
  - `_get_json_list`: `requests.RequestException` 과 HTTP 5xx 는 `_TransientVendorError`.
    4xx(410 폐지 등)·비 JSON·구조 불일치는 기존대로 `VendorUnavailableError`.
  - `_fetch_stock_news_json_with_retry` 신규: 같은 쪽을 `_STOCK_NEWS_RETRY_DELAYS = (0.5, 1.0)`
    초 간격으로 최대 2회 더 부른다 (총 3회).
  - `get_news`: 재시도 후에도 실패했을 때
    - 기간 끝(end) 이전 기사에 이미 닿았으면(`reached_window`) 읽은 만큼 반환하고 헤더에
      `⚠ 네이버 증권 HTTP 502 로 YYYY-MM-DD HH:MM 이후 기사만 조회됨 … 기사 없음으로 해석하지 마세요.` 를 붙인다.
    - 아직 닿지 못했으면 기존처럼 `VendorUnavailableError` (사유 포함).
- `tests/test_naver_news_vendor.py`: 재시도 대기를 없애는 autouse fixture + 신규 테스트 7건
  - 502 → 같은 쪽 재시도 성공, 네트워크 오류 재시도, 404/410 은 재시도 없음,
    첫 쪽 재시도 후 실패 → 예외(호출 3회·대기 0.5/1.0), 기간 안을 읽은 뒤 실패 → 부분 결과 + 경고,
    기간에 닿기 전 실패 → 예외.

## 설계 결정 변경 사항

- 이슈에서 열어 둔 재시도 횟수와 대기는 **2회, 0.5초·1초**로 정했다 (사용자 승인).
  근거: 2026-11-19 장애 때 같은 쪽을 다시 부르면 대개 성공했다 (502,200,502,200 …).
  100쪽 × 최대 3회라 최악의 경우 대기만 150초이지만, 장애율이 높은 구간에서만 생긴다.
- 부분 결과를 반환하는 조건은 "기사가 있으면" 이 아니라 **"기간 끝에 닿았으면"(`reached_window`)**.
  기간 안 기사가 노이즈·중복뿐이라도 경고가 붙어 "무보도" 로 오해되지 않고, 기간에 닿기 전
  (전부 더 최근 기사) 실패하면 부분 결과가 의미 없으므로 실패로 둔다.
- 경고에 시각(`HH:MM`)까지 넣었다. 기존 조회 한도 경고는 날짜만 쓰지만, 부분 조회는 하루 중
  어디까지 읽었는지가 중요하다.
- 재시도는 종목뉴스에만 적용. 주요뉴스(`get_global_news`)는 이슈 범위 밖이라 5xx 시 기존처럼 바로 실패.
