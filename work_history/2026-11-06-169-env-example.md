## 수행한 변경

- `.env.example` 전면 재작성: 코드가 실제로 읽는 변수만 — vendor 키(`DART_API_KEY`, `ECOS_API_KEY`, `NAVER_API_HUB_CLIENT_ID/SECRET`, `KRX_ID/PW`), 분석 설정(모델·effort·토론 라운드·언어·체크포인트·벤치마크), Claude 호출(`CLAUDE_CONCURRENCY`, `CLAUDE_TIMEOUT`), 경로, 웹 API(`API_PORT`, `API_CORS_ORIGINS`), `NO_UPDATE_CHECK`. 한국어 설명·기본값·키 발급처 기재.
- 삭제: 외부 LLM API 키 16종, FRED, SEC EDGAR, Bedrock, Ollama, TypeSafe, 제거된 provider/백엔드 URL/온도/토큰/재시도 변수, 미국 지수 `SPY` 예시.
- `tests/test_env_example.py` 신규: 예시의 모든 변수가 코드·compose 에서 읽히는지, vendor 키가 값 없이 있는지, 외부 LLM 키가 없는지.

## 설계 결정 변경 사항

- 사용자 `.env` 의 `KRX_API_KEY` 는 예시에 넣지 않았다 — #139 2단계(KRX Open API) 구상용 이름일 뿐 코드가 읽지 않는다. 구현되면 그때 추가한다.
- `TYPESAFE_*` 는 제외: `post_screen.py` 는 소셜 포스트 정제용인데 소셜 소스가 삭제(Task 7c)되어 어디서도 호출되지 않는다.
- `TRADINGAGENTS_CLAUDE_BARE` 는 넣지 않았다 — API 키가 있을 때만 쓰는 디버깅용 escape hatch (CLAUDE.md 4.6).
- `.env.enterprise.example`(Azure OpenAI)은 같은 상태이지만 이번 범위 밖.

## 검증 결과

- `pytest tests/test_env_example.py` 3 passed, `ruff check .` 통과.
- 변이 검사: 예시에 `OPENAI_API_KEY` 추가 → 외부 키 테스트 실패, `FRED_API_KEY` 추가 → 코드가 안 읽는 변수 테스트 실패, `KRX_PW` 삭제 → vendor 키 테스트 실패.
- 사용자 `.env` 의 키 이름(값은 보지 않음)이 `KRX_API_KEY` 를 제외하고 모두 예시에 있음.
